# CampusNet Project Rules

## 1. Frontend (client/)
- React 19 with Vite. Functional components with hooks (no classes).
- Tailwind v4 only for styling (no vanilla CSS unless absolutely required for global resets).
- Aesthetic: dark mode with neon accents (purple, cyan, pink) on near-black backgrounds. Match what's already rendered in the existing pages — do NOT redesign without explicit instruction.
- Icons: `lucide-react` exclusively.
- HTTP: `axios` for all API calls. Centralize axios instance in `src/lib/api.js` with base URL and auth header interceptor.
- State: React Context for global auth/user state (`AuthContext`). Local component state for everything else. Do not introduce Redux, Zustand, or any other state library.
- Routing: `react-router-dom` v7 (already installed). All protected routes go through `<ProtectedRoute>` wrapper that checks JWT presence and role.

## 2. Backend (server/)
- Node + Express + Mongoose.
- Folder structure: `routes/`, `controllers/`, `models/`, `middleware/`, `services/`, `utils/`.
- All API endpoints prefixed with `/api`. Example: `/api/posts`, `/api/auth/login`.
- Auth: JWT tokens in `Authorization: Bearer <token>` header. Middleware `requireAuth` and `requireRole(role)` for protected routes.
- Validate request bodies before hitting the DB. Reject malformed inputs with 400.
- Errors: throw or `next(err)`; do not silently swallow. Central error handler middleware returns clean JSON `{ error: message }`.

## 3. Data layer
- MongoDB Atlas (free tier).
- Every entity has a `college` field (hardcoded to `"SINHGAD_ENGINEERING"` for now). This is for future multi-tenant support — DO NOT remove it.
- Unique identifier for students is `rollNumber`, not email.
- `_id` (ObjectId) used as primary key everywhere; never expose in URLs as raw `_id` in user-facing forms — use it in API paths only.

## 4. Authentication
- Two account types: admin, student. JWT payload contains `{ userId, role: 'admin' | 'student' }`.
- Student email format: `firstname.rollnumber@college.edu`. Auto-generated by seed.
- Initial passwords stored hashed (bcrypt, 10 rounds). First-login forces password change via `mustChangePassword: true` flag on User document.
- Role state for students is computed at request time from collections: club membership, club presidency, communities managed/joined. Do not denormalize these into the user doc.

## 5. Secrets and environment
- All secrets (`MONGODB_URI`, `JWT_SECRET`, `GEMINI_API_KEY`) live in `.env` files.
- `.env` is gitignored; `.env.example` is committed with placeholder values.
- Never hardcode secrets in source files. Never log them.
- Frontend env vars prefixed with `VITE_`. Only public values (e.g., `VITE_API_BASE_URL`) — never API keys.

## 6. Mocking and faking
- If a backend feature blocks frontend progress, MOCK on the frontend immediately. Do not wait.
- Once backend is ready, swap mock for real call. Track all mocks with a `// MOCK:` comment so they're easy to find.

## 7. Working with existing code
- Before modifying an existing file, read it fully and understand what it does. Preserve existing functionality.
- Do not delete code to "clean it up" unless explicitly asked.
- When adding a feature near existing code, match the existing code's patterns (component style, naming, import order).

## 8. Code style
- Files: `kebab-case.jsx` for components is fine if existing code uses it; otherwise `PascalCase.jsx`. Match existing repo style.
- Functions: camelCase.
- Constants: UPPER_SNAKE_CASE.
- One component per file unless tightly coupled.
- Comments: explain why, not what. Skip them entirely if the code is self-explanatory.

## 9. Real-time
- Socket.io for personal DMs only.
- Polling (3s interval) for community General channel and notifications. Do not extend Socket.io to community channels for the first review.
- Socket events scoped to rooms: one room per connection pair (chat), no global rooms.

## 10. AI services
- Single Gemini wrapper in `server/services/gemini.js`. Function signatures:
  - `searchEntities(query, context) -> { clubs, communities, students }`
  - `summarizeStats(stats, context) -> string`
- Different prompts for AI Search, Live Ops Insights, Admin Insights — same wrapper.
- Always validate Gemini's JSON response; fall back to a structured empty result on parse failure.
- Never expose `GEMINI_API_KEY` to the frontend; all AI calls go through the backend.

## 11. Demo discipline
- Three days. Every feature has a fixed scope; do not expand without checking with the planning chat first.
- If something takes longer than the budgeted hours, STOP and reassess. Do not push through.
- Update `NOTES.md` at the end of each day with what was built, decided, broken, and deferred.
- Do not introduce new dependencies without checking; the stack is locked.
